# Internationalization (i18n) Guide

## Overview

The Classroom Finance App supports two languages:
- **English (EN)** - Default language
- **Portuguese (PT-BR)** - Secondary language

The application uses [next-intl](https://next-intl-docs.vercel.app/) for internationalization, which provides:
- Automatic locale detection
- Locale persistence via cookies
- Type-safe translations
- SEO-friendly URL structure

## URL Structure

All routes include a locale prefix:

```
/en/dashboard          # English
/pt/dashboard          # Portuguese
/                      # Redirects to /en
```

## Translation Files

Translation files are located in the `messages/` directory:

```
messages/
├── en.json           # English translations
└── pt.json           # Portuguese translations
```

### Translation Key Structure

Translations are organized hierarchically:

```json
{
  "common": {
    "buttons": { "save": "Save", "cancel": "Cancel" },
    "labels": { "name": "Name", "email": "Email" }
  },
  "dashboard": {
    "title": "Dashboard",
    "dre": { "title": "Income Statement" }
  },
  "students": {
    "title": "Students",
    "form": { "name": "Student Name" }
  }
}
```

## Using Translations

### In Client Components

```tsx
'use client';

import { useTranslations } from 'next-intl';

export function MyComponent() {
  const t = useTranslations();
  
  return (
    <div>
      <h1>{t('dashboard.title')}</h1>
      <button>{t('common.buttons.save')}</button>
    </div>
  );
}
```

### In Server Components

```tsx
import { getTranslations } from 'next-intl/server';

export default async function MyPage() {
  const t = await getTranslations();
  
  return (
    <div>
      <h1>{t('dashboard.title')}</h1>
    </div>
  );
}
```

### With Parameters

```tsx
// Translation: "Hello {name}!"
t('greeting', { name: 'John' })
// Output: "Hello John!"
```

## Navigation

### Using i18n Links

Always use the `Link` component from `@/i18n/routing` instead of Next.js Link:

```tsx
import { Link } from '@/i18n/routing';

export function Navigation() {
  return (
    <nav>
      <Link href="/dashboard">Dashboard</Link>
      <Link href="/students">Students</Link>
    </nav>
  );
}
```

### Programmatic Navigation

```tsx
import { useRouter } from '@/i18n/routing';

export function MyComponent() {
  const router = useRouter();
  
  const handleClick = () => {
    router.push('/dashboard');
  };
  
  return <button onClick={handleClick}>Go to Dashboard</button>;
}
```

## Language Switching

The `LanguageSwitcher` component is available in the navigation:

## Formatting

### Currency Formatting

Currency is always in BRL (Brazilian Real) but formatted according to locale:

```tsx
import { useFormatting } from '@/hooks/use-formatting';

export function PriceDisplay({ value }: { value: number }) {
  const { formatCurrency } = useFormatting();
  
  return <span>{formatCurrency(value)}</span>;
  // EN: R$ 1,234.56
  // PT: R$ 1.234,56
}
```

### Date Formatting

Dates use Brazilian timezone but format according to locale:

```tsx
import { useFormatting } from '@/hooks/use-formatting';

export function DateDisplay({ date }: { date: Date }) {
  const { formatDate } = useFormatting();
  
  return <span>{formatDate(date)}</span>;
  // EN: 02/09/2026
  // PT: 09/02/2026
}
```

### Number Formatting

```tsx
import { useFormatting } from '@/hooks/use-formatting';

export function NumberDisplay({ value }: { value: number }) {
  const { formatNumber } = useFormatting();
  
  return <span>{formatNumber(value)}</span>;
  // EN: 1,234.56
  // PT: 1.234,56
}
```

### Month Names

```tsx
import { useFormatting } from '@/hooks/use-formatting';

export function MonthSelector() {
  const { getMonthNames, getMonthName } = useFormatting();
  
  const months = getMonthNames();
  // EN: ["January", "February", ...]
  // PT: ["Janeiro", "Fevereiro", ...]
  
  const currentMonth = getMonthName(2);
  // EN: "February"
  // PT: "Fevereiro"
  
  return <select>{months.map(m => <option>{m}</option>)}</select>;
}
```

## Adding New Translations

### 1. Add Translation Keys

Add the same key to both `messages/en.json` and `messages/pt.json`:

**en.json:**
```json
{
  "myFeature": {
    "title": "My Feature",
    "description": "This is my new feature"
  }
}
```

**pt.json:**
```json
{
  "myFeature": {
    "title": "Minha Funcionalidade",
    "description": "Esta é minha nova funcionalidade"
  }
}
```

### 2. Use in Components

```tsx
const t = useTranslations();

<h1>{t('myFeature.title')}</h1>
<p>{t('myFeature.description')}</p>
```

## Translation Key Naming Conventions

Follow these conventions for consistency:

1. **Feature-based grouping**: Group by feature/page
   ```json
   "dashboard": { ... }
   "students": { ... }
   "expenses": { ... }
   ```

2. **Common elements**: Use `common` for shared UI elements
   ```json
   "common": {
     "buttons": { ... },
     "labels": { ... },
     "messages": { ... }
   }
   ```

3. **Nested structure**: Use nesting for related items
   ```json
   "students": {
     "form": {
       "name": "...",
       "email": "..."
     }
   }
   ```

4. **camelCase**: Use camelCase for keys
   ```json
   "monthlyReceipts": { ... }  // ✓ Good
   "monthly-receipts": { ... }  // ✗ Bad
   ```

## Best Practices

### 1. Never Hardcode Text

❌ **Bad:**
```tsx
<button>Save</button>
```

✅ **Good:**
```tsx
<button>{t('common.buttons.save')}</button>
```

### 2. Use Semantic Keys

❌ **Bad:**
```json
"text1": "Dashboard",
"text2": "Settings"
```

✅ **Good:**
```json
"dashboard.title": "Dashboard",
"settings.title": "Settings"
```

### 3. Keep Translations Synchronized

Always update both `en.json` and `pt.json` when adding new keys.

### 4. Use Parameters for Dynamic Content

❌ **Bad:**
```tsx
{t('welcome')} {userName}!
```

✅ **Good:**
```tsx
{t('welcome', { name: userName })}
// Translation: "Welcome {name}!"
```

### 5. Test Both Languages

Always test your changes in both English and Portuguese.

## Troubleshooting

### Missing Translation Keys

If you see the translation key instead of text:
1. Check if the key exists in both `en.json` and `pt.json`
2. Verify the key path is correct
3. Restart the dev server

### Wrong Language Displayed

1. Check the URL includes the correct locale prefix (`/en/` or `/pt/`)
2. Clear browser cookies
3. Check the `LanguageSwitcher` component

### Formatting Issues

1. Verify you're using the `useFormatting` hook
2. Check the locale is being passed correctly
3. Ensure the utility functions are imported from the correct path

## Configuration Files

### i18n/routing.ts
Defines available locales and default locale:
```ts
export const routing = defineRouting({
  locales: ['en', 'pt'],
  defaultLocale: 'en'
});
```

### i18n/request.ts
Configures message loading:
```ts
export default getRequestConfig(async ({ requestLocale }) => {
  // ...loads messages based on locale
});
```

### proxy.ts
Middleware for locale detection and routing:
```ts
export default createMiddleware(routing);
```

## API Routes

API routes do **not** include locale prefixes:
```
/api/students          # ✓ Correct
/en/api/students       # ✗ Wrong
```

The middleware automatically excludes API routes from locale routing.
